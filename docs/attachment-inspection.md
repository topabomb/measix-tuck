# 附件识别与模型上下文

## 当前契约

`inspect_attachments` 通过统一 Tuck MCP 接收有序的 1–4 个文件引用和识别要求，返回文字；输入参数见 [工具参考](tools-reference.md#附件识别1-个)，模型选择及开关见 [配置](configuration.md#附件识别模型)。

当前支持本地及 Runcove 的 PNG、JPEG、GIF、WebP，不支持 PDF、音视频或 Office。单件不超过 16 MiB、原始合计 48 MiB，复用 [图片准备规则](task-files.md#附件上传与图片准备)，模型表示合计不超过 16 MiB。只保存内存快照，不新增缓存或落盘文件。

本地只读范围是整个实际任务工作目录，包含项目文件及任意子目录，接受目录内相对或绝对路径；拒绝外部路径、URL、base64、目录、重复文件身份和越界链接。`os.Root` 限定读取，打开时检查文件身份，读取后核对根目录。auto/specified 可读；none 仅在引擎默认目录已知时允许本地只读，不增加写权限。

远程附件不依赖本地目录，复用本轮捕获的企业身份、空间及 DAV 授权。路径相对远端根目录，不接受 `/workspace/` 前缀，不自动切换空间或猜测连接；读取前后复核授权、文件版本和实际字节数。

## 执行与上下文边界

各 Agent 通过统一 MCP 入口携带明确调用者身份，要求活跃主任务 turn header，并核对其属于根 Agent 或配置的子代理树。专用识图不要求 TOOL 能力；只读子代理可独立选择模型，许可和目录不继承主助手全量工具。身份和连接规则见 [架构](architecture.md#tuck-原生工具集与-mcp)。

Files 负责本地图片，LocalTools 按 source 读取本地或远程输入并校验大小、许可和轮次，`model_content` 组织识图指令、有序标签和 request，Models 编码并发送一次无状态请求。支持 Chat Completions 和 Responses；不发送主聊天历史、主助手指令或工具。Responses 使用完整 input、`store=false`，不使用 previous_response_id。

本地复用 provider 地址及凭据；平台复用原始 runtimePath、admit、短期 access、managed generation 和 interaction ID。输出预算、显式 temperature/topP 沿用所选模型，推理档使用供应商默认。没有厂商域名特判、调用重试、工具递归、图片丢弃或模型回退。响应最多 4 MiB、有效文字最多 256 KiB，拒绝空结果、异常结束和超限。

不设识别总期限，阶段时限见 [超时与取消](configuration.md#超时与取消)。取消沿请求和响应体读取传播，发布结果前再次核对轮次、目录及身份。

成功文字由 Docker Agent 纳入当前上下文、后续轮次和分支；失败作为工具错误交给 Agent，字段和脱敏规则见 [工具返回合同](tool-results.md)。识别过程不创建原生会话，不改写引擎历史。

## 输入预览与来源身份

展开调用输入后按参数顺序显示缩略图，点击复用图片预览；本地可即时预览，远程在调用成功或错误后显示。浏览器只附加受保护文件地址，不把图片复制到历史或模型上下文。预览复用读取、解码和大小校验，显示当前文件而非历史快照；文件删除或不可读时明确失败。

远程来源身份来自该轮捕获的 workspace，保存在 Tuck tool-call presentation，不来自工具结果。按消息和调用块定位，读取时重新核对账号、空间、绑定版本及授权；切换账号或空间后不能打开同名新文件，也不能用当前登录身份猜历史归属。

分支根据父对话的工具名、callId 和完整输入匹配继承预览身份；候选缺失或不一致时不继承。不修改原生会话，不新增预览状态表或缓存。

## 不支持多模态时的实际行为

官方基线已通过隔离测试核对：`capabilities.image=false` 时，MCP 图片保存在公开历史中，后续聊天请求不包含图片像素。工具成功和界面有图都不能证明聊天模型已看见图片。生图工具会披露这一限制，只有识图确已获许可且可用时才建议调用。

用户上传图片时，IMAGE 聊天模型沿用原生多模态输入。纯文本聊天模型只有在识图已配置且获许可时才接受图片，收到路径和调用识别工具的指引，界面明确显示区别；不会自动调用识图或更换聊天模型，未配置时前后端均拒绝提交。

识图模型声明 IMAGE 但服务实际不支持时，服务错误进入工具结果，主 Agent 可继续解释；主聊天请求自身失败则由原生执行报告模型错误，没有成功续步可接收工具结果。Tuck 展示脱敏事实，不伪造消息、改写原生历史或接管重试。外部 MCP 的媒体仍由引擎处理。

协议及回归入口、实际字节和多图顺序、远程身份变更、纯文本主模型续步、历史/分支及页面检查集中在 [验证指南](verification.md#附件识别链路)。合成供应商只能证明传递合同，真实识别质量需用已授权服务单独验收。
