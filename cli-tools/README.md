# 独立命令行工具集

这里维护可单独构建、复制和执行的工具。每个工具拥有自己的入口、依赖、配置和测试，不导入 Tuck 的内部包，不读取 Tuck 配置，不接入其 MCP、任务或数据库。独立 CLI 的帮助、提示词和结果属于该工具，不经过 Tuck 的 `model_content.go`。

## 实现规范

- 每个工具一个语义明确的目录和可执行文件名，使用小写连字符；优先采用标准库和独立 Go module。通用函数放在独立 module `common/`，当前包含参数解析、帮助排版、退出码和 JSON 输出；业务规则留在工具内，不扩展成公共执行框架。
- 代码按实际职责分为少量文件，初期保持单个 package；不预设分层、插件系统、任务服务或持久化。
- 子命令使用动词，参数使用完整的 `--kebab-case` 名称；创建、查询、等待、下载的含义和副作用明确。不得通过静默换模型、换协议或重试创建请求掩盖失败。
- 无参数、`help`、`help <command>`、`<command> --help` 都应提供可用帮助。每个选项说明类型、默认值、必填/互斥关系及限制，并给出实例、认证方式、输出和退出码。
- 成功结果写 stdout，进度和错误写 stderr；可供脚本读取的结果用 JSON，`help`/`version`/`docs` 按各自文本格式输出。帮助不要求凭据或网络。凭据从显式环境变量或指定文件获取，不能内置、记录或自动读取宿主应用配置。
- 每个工具必须提供离线 `docs` 命令，将工具目录中唯一完整文档源文件 `README.md` 在编译时直接嵌入可执行文件，运行时原样写入 stdout。输出必须与编译时源文件逐字节一致，不拼接其他文档、生成参数参考、添加标题/版本或替换环境变量。搬走二进制、删除源码后仍能输出；不能运行时读取旁边的 README 或联网取文档。
- 长操作支持 Ctrl+C、明确的请求及等待超时；本地停止等待不宣称远端任务已取消。已经取得的任务 ID 应立即显示，便于后续独立查询。
- 文件默认不覆盖，先完成临时文件再发布；下载地址使用独立的无认证请求，不能转发供应商 API key。
- 基本测试覆盖命令解析/帮助、字段编码与验证、HTTP 成功/失败、异步终态、取消/超时、文件及凭据边界；使用本地 HTTP 夹具，不在默认测试中调用收费 API。真实验收按能力说明已验证和未验证范围。
- 源码、测试、独立 module、完整手册和构建脚本纳入本仓库 Git。构建产物统一放 `dist/<os>-<arch>/`，不提交二进制、校验文件、凭据、私有配置或生成素材；调研缓存和验收素材放仓库已忽略的 `.local/`。
- 提交前审查源码、测试、手册及嵌入内容中的隐私。非公开兼容服务用通用名称，示例使用 `example.com` 等保留示例域名和虚构数据；真实服务域名、账户信息、任务 ID、签名下载 URL、请求日志及素材不得进入 Git。协议实测仅保留匿名化结论，并注明日期与验证边界。

## 文档布局与职责

| 位置 | Markdown 文档 | 职责 |
| --- | --- | --- |
| `cli-tools/` | 仅本 `README.md` | 工具集规范、公共代码边界、工具索引和统一构建入口 |
| `cli-tools/<tool>/` | 仅 `README.md` | 该工具完整手册，也是编译嵌入与 `docs` 输出的唯一文档源文件 |
| `cli-tools/common/` | 无独立 Markdown | 小型公共函数通过代码注释和测试说明，使用边界在工具集规范中维护 |
| `dist/`、`.local/` | 不维护文档源文件 | 可放 `docs` 导出的手册快照；它是输出产物，不参与编译 |

每个工具的 `README.md` 应能单独阅读，包含用途和边界、快速开始、支持的模型/能力（若有）、连接与认证、全部子命令、全部参数的类型/默认值/适用范围/必填与互斥关系、素材或输入规则、完整示例、输出格式、退出码、超时/取消/文件行为、构建与验证方式。涉及外部服务时，将协议依据、差异、适配调研日期、实测结果和未验证边界作为该文件的章节。使用目录和 Markdown 标题组织长文。

不另建 `MANUAL.md`、`PROTOCOL.md`、快速开始副本、参数参考副本或文档目录。协议研究整理进同一个 `README.md`，缓存、素材和一次性运行记录保留在已忽略的 `.local/`。外部来源可用链接；使用手册自身的必要内容不能依赖其他本地文档。

Go 工具使用以下方式直接嵌入，`docs` 的输出使用标准库写入字符串即可，不需要公共文档拼装框架：

```go
import _ "embed"

//go:embed README.md
var manual string
```

修改命令、参数或行为时，同步维护 `README.md` 后重新构建。`help` 继续由真实参数定义提供即时命令帮助；测试至少验证 `docs` 输出与源文件字节一致、离线可用、写入失败可报告，并检查完整手册覆盖所有实际命令与参数，避免帮助和手册失配。验证使用现有 Markdown 源文件，不能让构建或 `docs` 临时生成完整手册代替它。

## 工具与构建

| 工具 | 用途 |
| --- | --- |
| [grok-video](grok-video/README.md) | xAI 视频生成、编辑、续接、查询与下载；支持兼容服务的显式 base URL |

需要 Go 1.26+，构建脚本使用 PowerShell 7：

```powershell
./cli-tools/build.ps1
./cli-tools/build.ps1 -Tool grok-video -Target windows-amd64,linux-amd64,linux-arm64,darwin-arm64
```

默认构建本机平台；构建前运行该工具的 `go test ./...` 和 `go vet ./...`，使用 `CGO_ENABLED=0` 生成独立执行文件。每个平台目录同时生成 SHA-256 校验文件。也可直接进入工具目录运行 `go test ./...`、`go run . --help`。
