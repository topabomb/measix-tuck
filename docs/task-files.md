# 任务文件与产物目录规范

本文是任务内文件布局、命名与落盘边界的唯一规则来源。Files 持有本地文件，LocalTools 绑定当前任务/轮次，Deliveries 持有独立交付副本；Docker Agent 只通过公开工具与文件路径参与，不接管其内部存储。

## 根目录与子目录

Tuck 自动管理的上传和生图文件统一位于实际任务工作目录的 `artifacts/` 下，按用途分子目录，按需创建，不建随机批次目录：

```text
<任务工作目录>/
  artifacts/
    uploads/upload_<Base62ID>-<原文件名>  # 用户上传的输入附件
    images/img_<Base62ID>.png            # 生图原文件，扩展名按实际格式
    images/img_<Base62ID>.prompt.txt     # 同名图片实际提交的提示词
    downloads/<可选子目录>/<源文件名>    # 可选下载位置，不是强制目录
```

`<Base62ID>` 使用 [ID()](../internal/tuck/types.go) 生成的 16 位 `0-9A-Za-z` 随机标识，不用 UUID，也不采用时间戳作为唯一标识。上传名会经过现有文件名清理；生成图的扩展名来自图片字节校验。生成图与上传文件独占创建，不覆盖已有文件；碰撞或写入失败明确失败，不改名重试。

`artifacts/` 及固定用途目录必须为普通目录，拒绝符号链接、junction 和打开期间的目录替换；子路径通过受限目录句柄访问。发布前重新检查目录身份，不能经目录链接把生成或上传写入其他用途目录或任务外。下载由调用者选择工作目录内的目标位置，仍禁止越出任务根目录。

后续 Tuck 生成的音频、转录等文件仍沿用此根目录，按实际实现再增加用途子目录；当前不创建这些目录，也不声明对应工具已实现。原生文件工具和 shell 可依照用户要求修改项目现有文件，Tuck 不重写它们的路径或强行移动项目源码。文件编辑接口只编辑已有文件，不另建输出根目录。

## 三种工作目录模式

| 模式 | 实际落点与权限 |
| --- | --- |
| `auto` | `<workspaceRoot>/<taskId>/artifacts/`，不同任务有独立目录；默认 workspaceRoot 为 `data/workspaces` |
| `specified` | `<指定的已有绝对目录>/artifacts/`；多个任务指定相同目录就共享文件空间，随机文件名不代表任务隔离 |
| `none` | Tuck 不上传附件、不编辑本地文件、不生成图片、不执行 DAV 下载；即使托管引擎有已知默认目录，也不能把它当作 Tuck 可写工作目录 |

助手配置只提供新任务的默认值，创建任务时的明确选择优先。已有任务和 fork 保留实际目录事实，不因修改助手配置移动文件。网页运行在客户端，以上目录均位于 Tuck 后端所在机器。

`none` 不改变 Docker Agent 原生文件/shell 能力，也不是运行时沙箱。会话协作不写工作文件；DAV 上传可读取已知任务目录内的源文件；交付工具可读取源文件并写入独立交付存储，仍校验路径、身份及授权。外接引擎默认目录未知时，不能猜测本地源文件位置。无文件摘要交付继续可用。

## 附件识别的只读范围

识别可只读访问整个实际任务目录或已授权 Runcove 空间，不产生文件；none 的本地只读例外、身份和路径校验见 [附件识别](attachment-inspection.md#当前契约)。

## 附件上传与图片准备

单个上传文件最多 16 MiB，每条消息最多 8 件且不能重复，其中图片原始字节合计最多 16 MiB。上传、登记和发送均核对当前任务，不能引用其他会话的附件。普通文件预览或下载最多 64 MiB，文本编辑最多 2 MiB；具体检查见 [files.go](../internal/tuck/files.go)，这些限制不作为 DAV 或交付文件的容量限制。

图片按实际字节解码，支持 PNG/JPEG/GIF/WebP，最多 40M 像素；动画还校验累计帧像素。模型表示修正方向，静态图片最长边缩至 2048px，动画保留原字节。原文件保持独立，识别、生成和聊天输入按各自合同校验数量与合计大小；生图参考图只校验并上传原字节，不用缩放后的模型表示替换它。

## DAV 上传与下载

上传的 `file_path` 相对整个任务工作目录，**不要求在 artifacts 下**，不移动或改写源文件；远端路径及平台授权规则保持有效。

下载的 `local_directory` 相对任务工作目录，例如 `review` 表示 `<任务工作目录>/review/`，`.` 表示任务根目录。`artifacts/downloads` 可作为目标但不强制。拒绝绝对路径、`..` 越界及逃出任务根目录的链接。成功文件通过 `files[].path` 返回相对整个任务工作目录的实际落点，不回显 `local_directory`；原生文件工具及 DAV 上传可直接使用该路径，不需要调用者再补前缀。

下载保留源文件 basename，批内同名拒绝。默认禁止覆盖；明确 `overwrite=true` 只替换任务目录内目标位置的普通文件。临时文件为目标目录内的 `.download_<Base62ID>.part`，下载字节数须与远端元数据一致；元数据有强 ETag 且响应携带 ETag 时也须一致。校验通过后原子发布，失败/取消清理该临时文件；已经完成的文件保留。详见 [DAV 工具参数和失败语义](tools-reference.md#企业-dav-文件交换2-个)。

企业文件管理页面的浏览器下载由浏览器选择客户端落点，不属于服务器任务目录；该页面的远端写入属于企业工作区，不在服务器额外缓存一套文件。

## 生图原图与提示词

每张原图与同名 `.prompt.txt` 一起发布。文本为发送给生图供应商的原始 `prompt`，保留换行和 Unicode，不是聊天用户原话的猜测，也不把它当作供应商内部改写后的提示词。一次返回多张图时，每张图各有对应提示词文件。工具文件结果返回 `path` 和 `prompt_path`，助手可一并交付。

对话历史通过现有媒体 provenance 保存本次调用的提示词；点击对话图片可查看和复制。任务产物中点击生成图片，读取其配套 `.prompt.txt` 并在同一预览中查看、复制；文件缺失或读取失败时保留图片预览并显示失败事实。用户手动修改旁边的提示词文件不会改写历史调用记录。

原图完整保存，模型表示按现有图片准备规则单独生成。对话中的图片通过标准 MCP ImageContent 进入官方引擎与历史媒体，可能经过缩放或格式转换，预览中的“打开图片”打开这一历史表示；任务产物中的“打开原图”读取工作目录内的完整原文件。供应商 URL 不作为永久文件位置。图片与提示词任一写入或最终发布失败，只清理本次独占创建的文件，不能递归清理共享的 `artifacts/images/`。

## 保留、交付与维护

参考图使用工具参数中明确指定的任务内相对路径，复用现有上传、生成或项目图片；只读原文件，不新增参考图缓存目录或上传到独立文件服务。文件读取通过任务 os.Root 校验边界、普通文件身份、大小及解码；拒绝越界链接和重复身份。参考路径及顺序保留在原生工具调用参数，`.prompt.txt` 仍只保存实际提交的文字提示词，不混入路径或结构化参数。

归档完整保留工作文件。设置中的“删除对话时清理自动工作文件夹”只控制 auto 模式；永久删除对话时，文件责任按实际目录归属区分：

| 目录模式 | 文件处理 |
| --- | --- |
| auto | 仅回收策略开启后新建、明确纳管且最后引用已解除的目录；fork 和子会话沿用同一目录身份，任一引用仍在则保留 |
| specified | 保留用户指定目录及全部工作文件；同路径、祖先或子目录的已知引用也会阻止托管目录回收 |
| none | 不清理引擎默认目录、公共目录或远程工作区 |

历史未纳管自动目录仍保留。开启回收意味着允许删除整个托管目录，包括上传、生成原图和用户源码的唯一副本，交付快照不代表全部文件已有备份。身份无法证明、目录替换或仍有 Tuck 在途使用时保留并显示原因。Tuck 的文件操作、原生轮次和创建新引用参加使用保护；无法跟踪任意宿主外部进程，需独立长期使用的目录应选择 specified。远程 Runcove 文件不纳入本地回收。

目录归属、状态和恢复详见[存储设计](database-design.md#统一删除对话)。任务产物列表仍展示实际目录中的文件，不把 `artifacts/` 之外的用户项目文件隐藏或搬迁。

交付副本独立位于 `<storage.dataDir>/deliveries/snapshots/<taskId>/<deliveryId>/files/<fileId>`，提交暂存使用同一存储的 `.staging/<deliveryId>/`。远程交付同样从已授权工作区读取并形成独立副本，无需先写任务目录。来源由原工具调用的 source/path 明确，快照仍使用原有文件 ID、路径、大小和摘要结构，不添加远程引用型交付。交付版本不能依赖可变工作文件，不能把这两个目录合并到 `artifacts/`；清理按 [交付存储规则](database-design.md#交付与清理) 执行。

Tuck 数据库、平台密文、`runtime/agent.yaml`、`native/`、`native-config/` 和 `engines/` 是应用/引擎资产，均不属于任务产物。完整备份范围见 [备份与恢复](persistence-migrations.md#完整备份与回退)。

选择 `specified` 目录时，现有可写性校验会在该目录短暂创建 `.tuck-access-*` 探针并立即删除；它是目录检查临时文件，不是产物，`none` 模式不执行这一检查。

不扫描工作根目录猜测所有权，不搬运或重解释历史路径。启动只依据已登记责任及已应用策略复查待回收目录。
